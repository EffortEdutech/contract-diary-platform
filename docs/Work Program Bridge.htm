Guideline: The Construction Work Program (CWP) Module 

Objective 

To provide a real-time Check & Balance between the theoretical schedule (MS Project/Primavera) and the physical truth recorded in the Daily Work Diary.

    • Revised Baselines: When a major Extension of Time (EOT) is granted, import a new version.

2. The Bridge: Linking Diary to Task 

For the "Check & Balance" to work, site activities must "talk" to the program tasks. 

  • Task Tagging: When a supervisor creates a diary entry, they should tag the relevant WBS Task from the imported program.
  • Physical Progress vs. Duration:
    • The Program tracks time elapsed.
    • The Diary tracks work done (e.g., "50m³ of concrete poured").
    • The Goal: If the program says a task is 50% through its duration, but the diary shows only 20% of the volume is installed, the module flags a variance. 

3. Monitoring the "Truth Gap" 

Use the module to visualize the discrepancies between the office and the field. 

  • Planned vs. Actual (P v A): Automatically generate a "S-Curve" or a simplified Gantt view that overlays the imported CSV bars with a progress bar fueled by daily diary entries.
  • Early Warning System (EWS): If a task has no diary entries for 3 consecutive days despite being "Active" in the program, the system should trigger a "Stagnant Task" alert.

2. Software Export Capabilities 

Both MS Project and Primavera P6 can export the required data to CSV or Excel formats. 

  • MS Project:
    • Duration: Exported by default.
    • Cost: Can export Total Cost or Budgeted Cost fields.
    • Man-Hours: Export the Work field (expressed in hours).
    • Note: You must use the "Export Wizard" in MS Project to map these specific fields to your CSV columns.
  • Primavera P6:

    • Man-Hours: Export "Budgeted Labor Units" or "Planned Labor Units".

  2. Mapping: User maps their CSV columns to these three types.
  3. Automatic Weighting: Your system calculates the relative weight for every leaf task based on the selection.
  4. Verification: Ensure the sum of all leaf task weights equals 100% (or 1.0) before proceeding with the % Actual calculation.
