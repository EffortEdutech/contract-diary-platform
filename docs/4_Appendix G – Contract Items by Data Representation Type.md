# Appendix G – Contract Items by Data Representation Type

This appendix classifies **all contract-related items** by **how they should exist in the platform**, so development is consistent, scalable, and legally defensible.

The four primary representation types are:
1. **Platform Form** – structured, system-native data (queryable, auditable)
2. **PDF / Static Document** – uploaded, versioned legal records
3. **Imported Data** – structured external files (Excel, Primavera, MS Project, CSV)
4. **Hybrid / Generated** – system-generated outputs from platform data

---

## G1. Platform Form (System-Native Records)

These items **must live as database records**, not files. They drive workflows, approvals, and evidence chains.

| Contract Section | Item | Reason |
|----------------|------|--------|
| Site Diary | Daily Site Diary | Primary factual evidence |
| Site Diary | Weather, Manpower, Plant | Claim substantiation |
| HSE | Toolbox Talks, Incidents | Statutory & liability |
| QA/QC | IR, NCR, Corrective Actions | Quality & payment linkage |
| Commercial | Instructions | Contractual authority |
| Commercial | Variations | Contract sum control |
| Commercial | Claims (EOT, L&E) | Entitlement logic |
| Commercial | Payment Applications | Cash flow control |
| Planning | Programme Reviews | Delay analysis |
| Subcontract | Subcontract Diaries | Back-to-back claims |

---

## G2. PDF / Static Legal Documents (Uploaded & Versioned)

These items are **legal instruments**. They should be uploaded as PDFs with:
- version control
- hash / checksum
- issue date & issuer

| Contract Section | Item |
|----------------|------|
| Pre-Contract | Tender Drawings & Specs |
| Contract Formation | Letter of Award / Acceptance |
| Contract Formation | Contract Agreement |
| Contract Formation | Conditions of Contract |
| Contract Formation | Appendix to Conditions |
| Contract Formation | Performance Bond |
| Contract Formation | Insurance Policies |
| Close-Out | Final Completion Certificate |
| Close-Out | Bond / Retention Releases |

---

## G3. Imported Data (Structured External Inputs)

These items originate outside the system but must be **parsed into tables**.

| Contract Section | Item | Typical Source |
|----------------|------|----------------|
| Pre-Contract | Tender BOQ | Excel / CSV |
| Contract Formation | Contract BOQ | Excel |
| Planning | Work Programme | Primavera / MS Project |
| Commercial | Contract Sum Analysis | Excel |
| Subcontract | Subcontract BOQ | Excel |
| Close-Out | Final Account Breakdown | Excel |

**Rule:** Imported files are retained, but **data lives in tables**.

---

## G4. Hybrid / Generated Artifacts

These items are **generated by the system** but often exported as PDF.

| Item | Generated From |
|----|----------------|
| Progress Report | Diary + BOQ |
| Delay Analysis Report | Programme + Diary |
| Claim Substantiation Bundle | Diary + Instructions + Programme |
| Payment Certificate | Certified Payment Data |
| HSE Summary Report | HSE Records |
| QA/QC Summary | IR / NCR Records |

---

## G5. Special Cases (Proposed Enhancements)

| Item | Representation | Notes |
|----|---------------|------|
| RFI | Platform Form + PDF Export | Audit trail |
| Meeting Minutes | Platform Form | Action tracking |
| Site Instructions (Verbal) | Platform Form | Later formalisation |
| Authority Submissions | Platform + PDF | Status tracking |

---

## G6. Design Rule (Non-Negotiable)

> **If an item affects time, cost, quality, or liability → it must exist as structured data first.**

PDFs are evidence, **not intelligence**.

---

## G7. Why This Matters

This classification:
- prevents misuse of file uploads
- ensures analytics & reporting work
- makes claims reconstruction deterministic
- keeps the platform legally credible

**This appendix should be used as a development rulebook.**
